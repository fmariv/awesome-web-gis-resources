# Contributing to Awesome Web GIS Resources

Thanks for helping improve this curated collection of Web GIS resources!

## What belongs here?

We welcome useful, publicly discoverable geospatial resources, especially:

- Browser-based GIS applications, map makers, visualization tools, and interactive explorers.
- Online geospatial processing, coordinate conversion, data editing, and utility tools.
- Public cloud-native geospatial catalogs (such as STAC), dataset discovery services, and Earth observation training-data repositories.
- Ready-to-use basemaps, tile services, and geospatial APIs with clear documentation or a usable interface.
- High-quality cartography and map-design guides, palettes, and practical reference material.

**This is a tools-and-services list, not a general index of programming libraries.** Standalone SDKs, libraries, frameworks, and packages are generally outside its scope; please suggest a working web app, explorer, service, or practical guide instead. Documentation-only links are appropriate for catalog/data access services or substantive cartographic guides.

Open-source, free, freemium, and commercial resources are eligible. Commercial status alone is not a reason for rejection.

## Quality criteria

A suggested resource should:

1. Have a working, direct URL and a clear geospatial use case.
2. Offer practical value beyond an existing entry, or explain a meaningful difference.
3. Have a usable web interface or a directly accessible service/catalog, or provide a substantive and practical cartographic guide.
4. Have enough public information to evaluate its capabilities, limitations, licensing, and access requirements.
5. Be reasonably maintained or remain useful as a stable reference, with an objective description rather than marketing copy.

We may decline duplicates, broken links, unrelated services, thin promotional pages, or resources that cannot be evaluated. Inclusion is at the maintainer's discretion and is not an endorsement.

## How to submit a resource

1. Search the README and open pull requests to avoid duplicates.
2. Fork the repository and edit `README.md`.
3. Add the resource under the most relevant category using the format:

   `- [Resource name](https://example.com/) — One-sentence description of what it does.`

4. Keep the description neutral and specific. If no suitable category exists, propose a clearly named new one.
5. Open a pull request and complete the PR template, including a brief explanation of its value.

Please keep changes focused and avoid unrelated formatting or reorganization in a resource-submission PR.

## Affiliation and transparency

Submitting your own project is welcome. **Disclose whether you are the creator, maintainer, employee, or otherwise affiliated with the resource.** Mention material limitations such as paywalls, required accounts, or significant usage restrictions where relevant.

## Reviewing and maintaining links

Maintainers review relevance, usefulness, duplication, accessibility, and documentation. Automated link checks can report false positives (for example, sites blocking bots); flagged links are reviewed before removal.

Be respectful and constructive in discussions. Thanks for contributing!
